# Database Standards

Classmate Connect — PostgreSQL

---

## General Principles

- PostgreSQL is the single source of truth.
- All schema changes go through Drizzle ORM migrations (not raw ALTER TABLE in production).
- Store UTC only. Never store local time.
- All tables carry `created_at`; mutable tables carry `updated_at`; all business entities
  carry `deleted_at` (soft delete).
- Never hard-delete business data. Use soft deletes.

---

## Naming Conventions

### Tables

Use `snake_case`, plural nouns.

```sql
courses
students
users
course_enrollments
assignments
assessments
notes
announcements
roles
permissions
role_permissions
user_roles
student_guardians
```

### Columns

Use `snake_case`.

Standard columns present on every table:

```sql
id              -- primary key
created_at      -- creation timestamp (timestamptz, NOT NULL, DEFAULT NOW())
updated_at      -- last-modified timestamp (timestamptz, NOT NULL, DEFAULT NOW())
deleted_at      -- soft-delete sentinel (timestamptz, nullable — NULL = active)
```

Foreign key columns:

```sql
course_id
student_id
teacher_id
user_id
role_id
permission_id
```

Audit columns (for audit-ready tables):

```sql
created_by      -- users.id FK
updated_by      -- users.id FK
deleted_by      -- users.id FK
```

### Primary Keys

Target standard: `uuid` (version 4, generated by the database).

```sql
-- Target
id uuid PRIMARY KEY DEFAULT gen_random_uuid()
```

Current state: `serial` (auto-increment integer). See Deviations section.

### Indexes

Use the `ix_` prefix. Pattern: `ix_{table}_{column(s)}`.

```sql
ix_courses_teacher_id
ix_course_enrollments_course_id
ix_course_enrollments_student_id
ix_student_guardians_user_id
ix_user_roles_user_id
```

### Unique Constraints (as indexes)

Use the `uq_` prefix. Pattern: `uq_{table}_{column(s)}`.

```sql
uq_users_email
uq_course_enrollments_active
uq_role_permissions
uq_student_guardians
```

### Check Constraints

Use the `ck_` prefix. Pattern: `ck_{table}_{rule}`.

```sql
ck_courses_status
ck_users_role
ck_assessments_score_range
```

### Primary Key Constraints

Use the `pk_` prefix.

```sql
pk_courses
pk_students
pk_users
```

### Foreign Key Constraints

Use the `fk_` prefix. Pattern: `fk_{table}_{referenced_table}`.

```sql
fk_courses_teacher_id
fk_assignments_course_id
fk_assignments_student_id
```

### Views

Use the `v_` prefix.

```sql
v_course_summary
v_student_progress
v_teacher_workload
```

### Functions

Use the `fn_` prefix.

```sql
fn_calculate_attendance
fn_student_average_score
fn_soft_delete
```

## Timestamps

Always use `timestamptz` (timestamp with time zone). Never use bare `timestamp`.

Drizzle ORM syntax:

```ts
createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
deletedAt: timestamp("deleted_at", { withTimezone: true }),
```

---

## Soft Deletes

All business entity tables must include a `deleted_at` column.

Rules:

- `deleted_at IS NULL` → active record.
- `deleted_at IS NOT NULL` → soft-deleted; treat as non-existent in all application queries.
- Never physically `DELETE` business data.
- All list queries must include `AND deleted_at IS NULL` (enforced via `isNull(table.deletedAt)`
  in Drizzle query builders).
- Detail (GET by ID) queries must also apply the soft-delete guard before returning data.

---

## Normalization

- Avoid denormalized arrays for relational data. Use junction tables.
- Avoid integer counters that duplicate what a `COUNT()` can compute.
- Computed values that change frequently should be derived at query time (or via a view),
  not stored as columns.

## Deviations from Standards (Current State)

See `docs/architecture/audit-report.md` for full risk assessment and remediation plan.

| Standard | Deviation | Tables Affected |
|---|---|---|
| IDs: `uuid` | Using `serial` (integer) | All tables |
| `updated_at` on all mutable tables | Missing | `assignments`, `assessments`, `notes`, `activity` |
| Indexes: `ix_` prefix | Using `idx_` prefix | `course_enrollments`, `student_guardians`, `user_roles` |
| Check constraints: `ck_` prefix | Using `chk_` prefix | `users` |
| Normalized FK for enrollments | `enrolledCourseIds` JSON array on `students` | `students` |
| Derived counts via view/query | `studentCount` integer column on `courses` | `courses` |
