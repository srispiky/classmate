## Objective

Certify database migration readiness for production. The platform historically relied on `drizzle-kit push` — a direct schema sync tool with no migration history, no version tracking, and interactive prompts that break automated deployments.

Production requirements addressed:
- Versioned migrations with audit trail
- Repeatable, non-interactive deployments
- Fresh environment provisioning
- Rollback strategy per migration type

## Part 2 — Migration Framework Design

### Strategy: `drizzle-kit generate` + `drizzle-kit migrate`

```
Schema edit (src/schema/*.ts)
    ↓
pnpm --filter @workspace/db run generate
    ↓ (creates SQL file + updates meta/_journal.json)
git add lib/db/migrations/ && git commit && git push
    ↓ (post-merge.sh auto-runs)
pnpm --filter @workspace/db run migrate
    ↓ (applies pending SQL, records hash in drizzle.__drizzle_migrations)
pnpm --filter @workspace/scripts run schema-smoke-test
    ↓
✅ 15 tables verified
```

| Command | Purpose | Environment |
|---------|---------|-------------|
| `generate` | Produce SQL from schema diff | Dev — after schema edit |
| `migrate` | Apply pending SQL files | CI/CD, post-merge, fresh installs |
| `push` | Direct sync, no history | **Dev only** — quick local iteration |

## Part 3 — Versioned Migrations Implemented

### Baseline migration: `0000_colorful_george_stacy.sql`

Generated by `drizzle-kit generate` from the live schema (15 tables). Modified for idempotency:

| Statement type | Before | After |
|---------------|--------|-------|
| `CREATE TABLE` | No guard | `CREATE TABLE IF NOT EXISTS` |
| `CREATE INDEX` | No guard | `CREATE INDEX IF NOT EXISTS` |
| `ALTER TABLE ADD CONSTRAINT` (×43) | Would fail on existing DB | Wrapped in `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object THEN NULL; END $$;` |

**Migration journal:** `lib/db/migrations/meta/_journal.json` (drizzle v7 format)  
**Schema snapshot:** `lib/db/migrations/meta/0000_snapshot.json` (baseline for future diffs)

### Old hand-written files deleted

| File | Reason for deletion |
|------|---------------------|
| `0000_baseline.sql` | No-op placeholder — superseded |
| `0001_integrity_constraints.sql` | FK constraints captured in drizzle baseline |
| `0002_add_push_token.sql` | `push_token` column captured in drizzle baseline |

## Part 4 — Rollback Strategy

| Migration type | Rollback approach | Notes |
|---------------|-------------------|-------|
| **Additive** (new column, index, table) | Write a new forward migration that reverts it | Safe, no data loss |
| **Data migration** | Standalone script; restore from pre-migration `pg_dump` | Manual step |
| **Destructive** (DROP TABLE/COLUMN) | Restore from backup — **cannot auto-rollback** | Requires `pg_dump` before merge |

**Limitation:** drizzle-kit has no `migrate down` command. All rollbacks are forward-only (write a corrective migration).

Each migration runs inside a PostgreSQL transaction — a mid-migration failure automatically rolls back that migration's DDL.

## Part 6 — Deployment Integration

### Updated `scripts/post-merge.sh`

```
pnpm install --frozen-lockfile
pg_isready check (connectivity pre-flight)
pnpm --filter @workspace/db run migrate     ← was: drizzle-kit push
pnpm --filter @workspace/scripts run schema-smoke-test
```

Changes:
- `push` → `migrate`: non-interactive, versioned, CI-safe
- Silent auth-failure detection retained (drizzle-kit may exit 0 on pg errors)
- `set -e` ensures any failure aborts the script

### Session table protection

Added to `lib/db/drizzle.config.ts`:
```typescript
tablesFilter: ["!session"]
```
Prevents `drizzle-kit push` (dev mode) from ever prompting to drop the session table.
