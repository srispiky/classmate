--------------------------------------------------
OBJECTIVE
--------------------------------------------------

Eliminate Risk R-H3.

Current finding:

Backups are generated successfully but remain on the same platform.

There is no offsite copy.

A platform outage, storage failure, accidental deletion,
or repository compromise could destroy all backups.

Implement secure offsite replication.

--------------------------------------------------

Review:

- backup locations
- retention policy
- backup workflow

Verify:

- where backups are stored
- how long backups survive
- current failure scenarios

Document findings.

--------------------------------------------------
PART 2 — OFFSITE STORAGE DESIGN
--------------------------------------------------

Implement offsite replication architecture.

Requirements:

- provider agnostic
- environment driven
- no hardcoded credentials
- encrypted transport
- retry support

Examples:

- S3 compatible storage
- Azure Blob Storage
- Google Cloud Storage

Design abstraction so storage provider can be changed later.

--------------------------------------------------
PART 3 — REPLICATION SERVICE
--------------------------------------------------

Create:

BackupReplicationService

Responsibilities:

- upload backup artifacts
- upload metadata sidecars
- verify upload success
- return replication status

Requirements:

- idempotent
- testable
- isolated from backup generation

Do not modify backup logic.

Reuse existing backup outputs.

--------------------------------------------------
PART 4 — CHECKSUM VERIFICATION
--------------------------------------------------

Implement:

Checksum verification after upload.

Verify:

- uploaded file size
- checksum match
- metadata integrity

Fail replication if verification fails.

--------------------------------------------------
PART 5 — GITHUB ACTIONS INTEGRATION
--------------------------------------------------

Extend backup workflow.

After successful backup:

1. Execute replication
2. Verify replication
3. Publish replication report

Fail workflow if:

- upload fails
- checksum mismatch
- metadata missing
