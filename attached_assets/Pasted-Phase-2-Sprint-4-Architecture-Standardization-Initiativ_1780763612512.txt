Phase 2 – Sprint 4

Architecture Standardization Initiative

# Goal

Standardize Classmate Connect around a single architecture, naming convention, database convention, and coding standard.

This is an architecture governance task.

Do not introduce new business features.

Do not implement Enrollment Management.

Do not implement new APIs.

Focus on establishing and documenting standards, auditing the current implementation, and identifying deviations.

# Background

Classmate Connect uses:

* Node.js
* Express
* TypeScript
* PostgreSQL
* Drizzle ORM
* Zod

Architecture style:

* Enterprise architecture
* Layered architecture
* RBAC
* RLS
* Policy-based authorization
* Soft deletes
* Audit-ready design

The project is adopting PostgreSQL-first conventions.

# Architecture Standards

Controllers

Responsibilities:

* request validation
* service invocation
* response mapping

No business logic.

No authorization logic.

Repositories

Responsibilities:

* database access only

No business rules.

No authorization decisions.

Services

Responsibilities:

* business logic

Policies

Responsibilities:

* authorization only

Validators

Responsibilities:

* scope and ownership decisions

# Authorization Standards

Authorization logic must exist only in:

* Policies
* Validators
* Scope helpers

Authorization logic must not exist in:

* Controllers
* Repositories

All resource access must flow through:

```text
Layer 1
Route authorization

Layer 2
Query filtering

Layer 3
Post-fetch validation
```
