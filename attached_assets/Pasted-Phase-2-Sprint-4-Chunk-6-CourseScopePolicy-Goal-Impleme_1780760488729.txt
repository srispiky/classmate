Phase 2 – Sprint 4

Chunk 6 – CourseScopePolicy

# Goal

Implement CourseScopePolicy using the ResourceScopePolicy framework and TeacherScopeValidator.

This is the first policy that fully supports:

* Admin ownership model
* Teacher ownership model
* Student enrollment model
* Parent child-enrollment model

The policy becomes the authorization engine for Course resources.

# Current Infrastructure

Already implemented:

* ScopeContext

* SessionEnricher

* teacherId

* ownedCourseIds

* enrolledCourseIds

* childCourseIds

* CourseScopeValidator

* TeacherScopeValidator

* ResourceScopePolicy framework

Reuse existing infrastructure.

Do not duplicate authorization logic.

Do not perform additional database lookups.

# Objectives

1. Create CourseScopePolicy
2. Implement Layer 2 query filtering
3. Implement Layer 3 ownership validation
4. Integrate Teacher ownership model
5. Add unit tests
6. Preserve existing behavior

# Authorization Rules

Admin

* Global access

Teacher

* Access only owned courses

Rule:

```ts
course.id IN scope.ownedCourseIds
```

Student

* Access only enrolled courses

Rule:

```ts
course.id IN scope.enrolledCourseIds
```

Parent

* Access only child courses

Rule:

```ts
course.id IN scope.childCourseIds
```

# Policy Location

Suggested location:

```text
src/shared/auth/policies/course-scope-policy.ts
```

# Policy Responsibilities

The policy must:

1. Filter course queries
2. Validate course access
3. Centralize course authorization

Services must not contain role-specific authorization logic.

All authorization decisions should flow through the policy.

# Layer 2 – Query Filtering

Implement:

```ts
applyFilter(
  query,
  scope
)
```

Behavior:

Admin

* no filtering

Teacher

```sql
WHERE course.id IN ownedCourseIds
```

Student

```sql
WHERE course.id IN enrolledCourseIds
```

Parent

```sql
WHERE course.id IN childCourseIds
```

Requirements:

* Use TeacherScopeValidator
* Use existing query filter infrastructure
* No in-memory filtering
* No post-processing arrays
* Database-level filtering only

# Layer 3 – Access Validation

Implement:

```ts
validateAccess(
  scope,
  course
)
```

Behavior:

Calls:

```ts
validateCourseAccess(
  scope,
  course.id
)
```

Requirements:

* Reuse TeacherScopeValidator
* Throw existing AuthorizationError
* No duplicated ownership logic

# Policy Design

The policy should be lightweight.

Avoid:

```ts
if (role === ...)
```

logic repeated throughout the policy.

Delegate authorization decisions to:

```ts
TeacherScopeValidator
```

and related shared helpers.

# Expected Usage

Future CourseService usage:

```ts
coursePolicy.applyFilter(
  query,
  scope
);
```

and:

```ts
coursePolicy.validateAccess(
  scope,
  course
);
```

No service should need to know role-specific ownership rules.
